1. 主协调：共享 IR 和配置契约、集成、文档、安装验证、真实 museon 扫描与诊断复核。
2. 核心 agent：纯 Rust 对象 / 别名 / 移动 / 资源 / 借用状态，结构化控制流与相关单元测试。
3. Python agent：tree-sitter 前端、符号 / 导入解析、无标注效果推断、已知 API 模型、向共享 IR 降低。
4. CLI agent：配置发现、文件遍历、文本 / JSON、规则选择、strict、退出码和 CLI 测试。
5. 验证 agent：独立语义用例和对抗性回归，检查第一版所有权和借用不是只有表面模式匹配。
6. museon inventory agent：只读定位目标仓库、语言配置和实际使用模式。

## 语义边界

普通赋值与传参不是 move。已建模的 os.open → os.fdopen 协议或配置中的 consumes 声明建立明确转移边界；内置资源协议、可证明效果、迭代借用提供零标注默认检查。资源关闭会使对象失效。同步调用的只读 / 可变借用来自已解析函数效果或可信库契约。持久借用需要已知视图关系或明确返回借用契约。

由迭代推导的借用属于 Rust 风格限制策略；Python 本身允许的某些修改仍可能被策略拒绝。未建模动态行为必须显示为 coverage gap；strict 不得将未覆盖当成通过。分析不执行用户代码。第一版不宣称对任意 Python 提供完整 Rust 安全证明。

## 架构选择更新

本轮先使用 tree-sitter-python 0.25 解析器，独立于 Ruff monorepo，避免初版被其内部 crate 接口绑定。规则核心仅消费语言无关的结构化控制流 IR。以后 Go / TS 的前端可复用状态分析与诊断，但需独立实现其复制、别名和库语义。
