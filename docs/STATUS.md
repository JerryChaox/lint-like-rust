# 实现状态

2026-09-13：本地 alpha 已实现，核心、前端、CLI 与独立语义测试已集成。项目不是对任意 Python 的 Rust 编译器级安全证明。

## 第一版实际能力

| 层 | 已实现 | 当前边界 |
|---|---|---|
| 所有权 | 对象身份、别名、显式转移、转移后的使用和重复转移 | 默认建模 `os.open → os.fdopen` 成功路径；业务边界可通过配置声明 `consumes`；普通赋值和传参不是 move |
| 借用 | 共享 / 独占借用、再借用、活跃区间、最后使用点、借用冲突、借用期间转移 / 关闭 | 默认来自已知集合迭代 / 视图与同文件可解析函数效果；任意用户类型、字段和跨模块关系尚不完整 |
| 生命周期 | 已知文件 / 原始描述符关闭、别名失效、with / finally 清理、返回失效资源 | 未通用建模网络响应、数据库事务、锁、任务、任意上下文管理器 |
| 返回值 | 可信 must_use 契约、部分可证明无副作用且返回非 None 的函数 | 不按所有函数调用一概判断“返回值必须使用” |
| 控制流 | 分支、循环、返回、break / continue、异常处理与清理；区分 definite / possible | 异常派发与动态行为存在缺口；达到求解预算时明确记录未验证 |
| 工具 | pyproject 配置、gitignore、排除项、规则筛选、文本 / JSON、抑制审计、strict、pre-commit 入口 | 尚无公开发行、编辑器服务、跨模块增量索引 |

默认不需要源码标注。可选项目契约是可信输入，报告记录实际配置来源。检查器只读取源码，不导入或执行目标 Python。

## 不应误读的结论

- 所有权、共享 / 独占借用及再借用检查已经进入第一版；Python 前端覆盖的是明确的语义子集。
- 迭代 / 转移检查包含额外的 Rust 风格策略，部分合法 Python 写法会被限制；诊断不必然是已经发生的运行时 bug。
- Python 返回局部对象本身合法；对象仍被变量引用也不等于借用仍活跃。
- 跨模块调用、字段 / 下标对象身份、反射、动态调用、复杂参数绑定、异步和并发关系需要进一步实现。
- `os.fdopen` 构造异常、`tempfile.mkstemp` 的解构来源、`open(fd)` 尚未完整建模。不能据此宣称已验证 Museon 的所有描述符流转。
- 每个分析单元设有路径、循环收敛和语义步骤上限（128 状态、8 轮、10000 步）；超限产生 coverage gap，不是安全证明。
- 默认退出 0 只表示没有所选规则诊断及扫描错误；`--strict` 会因分析缺口退出 1。解析 / IO / 配置错误退出 2。

## 验收

最终验收：131 项测试通过（核心 40、Python 前端 36、独立语义 45、CLI 10），`cargo fmt --check` 和 `cargo clippy --all-targets -- -D warnings` 通过，release 构建成功。本机通过 uv 安装的命令已验证。真实扫描统计见 [Museon 报告](../reports/museon.md)。独立回归覆盖合法反例、错误用法和未覆盖行为；安全示例 `examples/safe.py` 无诊断且无分析缺口，`examples/violations.py` 可检出 OWN001、BOR002、LIFE001。

## Museon 实测

最终 release 扫描十个产品源码根：2,585 个 Python 文件，91.698 秒，0 诊断、0 扫描错误；2,329 个文件存在分析缺口，共 556,300 条缺口记录，其中 2,060 条涉及求解预算。缺口数量不是 bug 数量，也不是覆盖率。当前结果不能证明 Museon 安全，尚不适合作为其全面的 CI 安全门禁。

Museon Git 状态清单在扫描前后相同，未修改其源码或配置。JSON、摘要和二进制摘要对应本次最终构建。

## 后续开发顺序

1. 利用 Museon 实测缺口建立跨模块符号索引和可缓存调用效果摘要。
2. 增加字段 / 容器元素身份、资源返回关系与未知调用后的效果传播。
3. 增加 Museon 使用的 mkstemp、HTTP 流、数据库事务、任务和锁的精确协议模型，并配套合法反例。
4. 以独立测试语料衡量误报、漏报与分析覆盖，再决定何时接入 CI 阻断。
5. Go / TS 分别增加前端和语义模型，复用语言无关 IR、状态求解、规则证据与报告协议；不需要重写所有工作。
