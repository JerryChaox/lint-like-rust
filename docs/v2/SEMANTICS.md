# V2 语义规范：面向智能体的安全检查

状态：**设计规范，非已经实现的能力清单**。2026-09-13。

本文规定目标分析的含义与验收条件。当前 `src/ir.rs` 原型只有以字符串变量为中心的结构化操作、诊断和缺口列表；它没有实现本文完整的项目符号、字段位置、效果摘要或证明范围。实现必须逐项标明支持程度，不能因为存在对应规则编号就声称满足规范。

## 1. 产品契约

`llr` 是静态分析器，不执行或导入被检查的 Python，不改变其运行时行为。目标是为智能体提供稳定的、带因果证据和修复约束的反馈。

每项检查义务返回以下结果之一：

- **violation**：有证据表明违反规则。另行标记 `definite`（在建模的所有到达状态中违规）或 `possible`（存在抽象违规状态）。抽象的 possible 路径未经可行性确认，不得表述为必然可执行的复现。
- **verified**：在报告明确列出的输入假设、可信模型和分析边界内，该义务的所有到达状态均满足规则，而且没有影响该义务的未解决未知项。
- **unverified**：动态行为、缺失语义或求解预算使该义务无法判定。报告影响范围和阻碍原因。

扫描没有诊断不等于 verified。三种结果按“义务”划分；同一函数可以有一项 violation 和另一项 unverified。没有进入已建模操作的文件也不能因此获得 verified。

## 2. Python 事实与附加策略分开

| 类别 | 规则含义 | 例子 |
|---|---|---|
| 运行语义约束 | 基于已解析对象协议，操作不适用于当前状态 | 对已经关闭的文件执行读取 |
| 所有权策略 | 转交某项管理权限后，原权限持有者不能继续使用该权限 | 将描述符交给拥有它的包装对象后，继续经原权限操作 |
| 借用策略 | 活跃共享借用禁止冲突写入；独占借用限制其他访问 | 持有集合迭代借用时进行结构修改 |
| API 契约 | 显式可信模型要求使用返回值或履行某种义务 | 必须消费的结果被丢弃 |

策略违规不自动等于 Python 运行时错误。普通赋值、普通传参和返回局部对象都不自动转移或销毁资源。对象有多个引用本身合法。`close` 是否幂等、哪些操作在关闭后仍可用，属于具体协议，不能由方法名统一决定。

默认零源码标注：效果来自静态推导和有出处的外部模型。无法推导不等于任意猜测。项目可选契约属于可信假设，须记录来源及摘要；不能藏在实现中。

## 3. 前端提交什么事实

核心不消费 Python AST 节点或字符串方法名。前端提供带源码出处的语义事实：

1. 符号身份：模块、词法作用域、定义身份以及绑定／重绑定。
2. 类型与调用候选：候选集合、是否穷尽、依据。仅有类型信息不等于已知副作用。
3. 控制流：基本块、条件边、正常边、异常边和清理边。
4. 对象操作：分配、位置读取／写入、调用、协议状态转换、权限操作。
5. 不确定事实：不能解析的调用、动态属性、候选不穷尽及其影响区域。

`Path.open` 的外部模型应绑定到解析后的定义身份和适用条件，而非看到 `.open()` 就套用。局部同名函数、猴子补丁和不确定动态派发会改变解析结论。模型可以是手工维护的库知识；推理引擎不能由 API 名称分支取代。

## 4. 抽象状态与对象身份

### 4.1 位置、对象和权限是不同概念

- **位置 Place**：局部绑定、对象字段、容器常量键／元素摘要，例如 `Local(f,x)`、`Field(o,name)`、`Element(o,"a")`、`Element(o,*)`。
- **对象 ObjectId**：分配点加有界调用上下文。循环分配可合并为摘要对象，不能当作唯一运行时实例。
- **资源 ResourceId**：具有状态协议的底层实体。包装对象可以管理同一底层资源。
- **权限 CapabilityId**：谁可以以何种方式操作该资源。权限移动不等于资源关闭。
- **借用 LoanId**：针对资源／位置区域授予的共享或独占访问权，含父权限、创建位置、结束条件。

两个变量可能指向同一个对象；两个不同包装对象也可能管理同一个资源。别名、资源关系和权限传播要分别表示。

### 4.2 抽象域

分析状态可表示为以下积域；实现可换用等价结构，但必须保留这些区分：

```text
State = (Reachable, PointsTo, Heap, Protocols, Capabilities,
         Loans, Escapes, PathFacts, Uncertainty, Evidence)
```

- `PointsTo/Heap`：位置到可能对象集合，含 unknown 标记；另保留确定别名关系。单元素集合只有在对象非摘要且位置唯一时才能用于强更新。
- `Protocols`：每个资源的可能状态集合，如 `{open}`、`{closed}`、`{open,closed}`，以及模型专有状态；未知状态不是 closed。
- `Capabilities`：可能权限状态 `{available, transferred}` 等，以及权限与对象／资源的联系。
- `Loans`：可能活跃借用与确定活跃借用；借用区域及共享／独占模式。
- `Escapes`：对象是否被返回、存入外部可达堆、交给未知调用或异步任务。
- `PathFacts`：保留的条件事实，精度不足时允许丢弃，但不能用丢弃后的条件证明互斥。
- `Uncertainty`：带依赖关系的未知原因和影响区域。
- `Evidence`：状态转换的来源和前驱，用于构造可读证据链。

`bottom` 表示不可达；`top` 表示该域任意可能值。**未知不能解释为“无副作用”或“未关闭”。**

## 5. 转换、分支合并与求解

赋值 `b = a` 拷贝对象引用关系。更新 `a = new_value` 只重绑定该位置，不改变 `b` 引用的旧对象。字段写入则修改对应堆位置。

强更新仅适用于确定唯一位置；存在别名候选或摘要对象时使用弱更新。对不确定键写入，要影响可能重叠的元素区域；不能假定它与已有常量键不相交。

分支合并按抽象上界运算：可能对象／状态取并集；确定事实取交集。例：一个分支关闭、另一个分支保持打开，合并为 `{open,closed}`，后续读取不能报 definite，也不能 verified。仅当可行性和所有前驱证明允许时才能收紧结论。

循环和递归使用单调工作列表及不动点计算。有限域或显式 widening 保证收敛；widening 可以增加 possible/unverified，不得制造验证结论。预算耗尽时，未完成范围标记 unverified 并污染依赖的义务，不能直接把当前状态当最终结果。

每个 transfer function 必须给出读集合、写集合、状态转换和异常结果。原型的固定展开次数不构成任意循环的证明。

## 6. 未知调用与 havoc

无法解析 `f(x)` 时，至少考虑它可读取、修改、关闭或保存 `x` 可达的对象，返回别名或新对象，并可能抛出异常。对受影响区域执行保守 `havoc`，使依赖这些状态的结论 unverified。

影响区域不仅是显式参数：还包括接收者、闭包捕获、该调用可访问的模块／全局状态和已经逃逸的共享对象。若无法约束可达区域，则扩大范围，必要时使当前单元整体未验证。不能声称任意动态 Python 下都有精确且局部的 havoc。

不相交且有证据证明未暴露给调用的局部对象可保留精确信息。来源于未知调用之前的独立违规也无需被全局删除。每个未知必须说明“什么事实不再可信”和“哪些义务受到影响”，不只累计一条文本计数。

## 7. 函数效果摘要与调用组合

摘要以解析后的定义身份、输入条件和分析版本为键，内容至少包括：

```text
preconditions
reads / writes / structural_writes
closes / transfers / escapes
returns: fresh | alias(parameter-or-field) | borrowed(region,mode) | unknown
normal_postconditions
exceptional_postconditions (可按异常种类合并)
unknown_effects + provenance + completeness
```

调用点进行真实参数绑定，处理默认值、接收者和关键字；绑定不确定时不能盲目按位置套用摘要。多目标调用合并所有候选效果；候选集不穷尽则还要加入未知效果。

函数体推导、已验证配置契约和外部模型必须区分出处。递归调用图的强连通分量共同求不动点；摘要缓存依赖函数体、被调摘要、配置和模型版本。改变其中任何项应使相关结果失效。

正常返回后置条件不能套用到异常路径。例如包装资源的构造调用，成功时转移管理权限；失败时是否转移必须由具体契约给出，未知则保留未验证分支。

## 8. 所有权与借用

### 8.1 转移

`transfer(capability, recipient)` 撤销原持有者的对应访问权限，同时把权限交给接收者。底层资源通常仍然有效。与原权限关联的别名继续使用原权限时违规；接收者通过新权限访问可以合法。

如果只将抽象对象标成 moved，接收者也会被错误禁止访问，因此对象身份不能替代权限身份。若一个别名此前已获得独立合法权限，是否受影响由该权限规则决定，不能一律失效。

### 8.2 借用区域与冲突

共享借用允许共享读取，禁止对重叠区域的冲突写入；独占借用只允许经该借用或合法子借用的访问。移动或关闭被借用的资源同样构成冲突。字段精度充分时，不相交字段可分别借用；无法证明不相交时保守认为可能重叠。

是否“结构写入”、是否使迭代／视图失效由协议和策略说明。不能把任何方法调用都当写入，也不能把每个字段读取都当创建借用。

### 8.3 活跃区间与再借用

借用活跃区间通过 CFG 上的后向需求及前向存在性共同求解，包括分支、循环、异常清理和借用句柄别名。源代码最后一行引用不是通用生命周期算法。

子借用存活期间，父独占权限对应区域暂停；子借用结束后可恢复。借用句柄被保存、返回或交给未知调用时，不能在当前局部最后使用点结束它；需要摘要边界或明确未验证。

Python 普通引用不天然是 Rust 借用。只有协议操作、推导出的调用期效果或显式安全策略建立借用；推断过程及限制需要可解释。

## 9. 异常、清理与退出

CFG 必须保留调用和相关操作的异常边，`return`、`break`、`continue`、异常传播都经过适用的 `finally`/上下文退出。清理本身也可能抛异常，并可替代原返回／异常结果。

上下文进入值不必等于管理器对象；退出方法可能抑制异常，也可能不关闭资源。仅在已解析的协议模型成立时，才能将 `with` 降低成“退出时 close”。

返回值先求值、再执行清理、最后交给调用方。若返回值引用的资源在清理中失效，则调用方收到失效资源；返回局部堆对象本身没有错误。

`async`、取消和并发调度不在首个同步切片的验证范围内。不得仅因遇到 `await` 就判借用违规，也不得以顺序 CFG 证明并发安全；需要单独语义扩展。

## 10. 推导示例

### A. 跨函数别名与关闭

```python
def identity(value):
    return value

resource = open("example.txt")
alias = identity(resource)
resource.close()
alias.read()
```

摘要推导 `identity.returns = alias(arg0)`。调用后两位置指向同一资源；已解析文件 close 正常后置条件使资源 closed；read 要求 open。若该路径没有影响状态的未知，输出 definite 的生命周期违规，证据包含分配、摘要返回关系、关闭和访问四步。

### B. 分支关闭

```python
if condition:
    resource.close()
resource.read()
```

前提是 resource 已知打开且条件两边均可能到达。合并结果 `{open,closed}`，输出 possible；条件无法支持实际可行性证明时明确标注抽象路径。禁止输出 definite。

### C. 未知不能当修复

```python
unknown_extension(resource)
resource.read()
```

调用可能关闭 resource；相关读取义务 unverified，并记录未知调用作为阻碍。把示例 A 的 close 换成未知包装调用不能让报告宣称“已修复”。

### D. 字段重绑定

```python
holder.stream = resource
alias = holder.stream
holder.stream = replacement
resource.close()
alias.read()
```

在 holder 身份唯一的前提下，字段重绑定不改变 alias 指向旧对象。最后读取仍违反关闭状态约束。若 holder 是不确定摘要对象，则使用弱更新并降低结论精度。

### E. 所有权接收者仍能访问

```text
创建资源 R 与权限 C1
a、b 引用 R 且使用 C1
向 wrapper 转交 C1，wrapper 获得 C2
通过 b / C1 操作：所有权策略违规
通过 wrapper / C2 操作：允许，前提 R 的协议状态有效
```

这是分析规则示例，不声称任何普通 Python 包装操作天然满足该转移契约。

## 11. 诊断与智能体验收

诊断输出必须包含规则类别（运行约束／策略／契约）、义务、相关资源／权限、主要位置、跨调用证据链、可行性／置信度、模型与假设、修复约束。资源显示身份应能映射回源码，而非要求智能体理解内部编号。

修复建议描述必须恢复的条件，不提供未经验证的自动修改。两次报告比较至少区分 resolved、persists、introduced、became_unverified 和 out_of_scope；规则关闭、文件排除、添加抑制不能作为 resolved。

每个声称支持的能力必须经过：

1. 语义正例与合法反例，包括改变量名、增加中间别名、跨函数封装后的等价结果。
2. 分支、循环、异常及未知干扰测试，检验 definite/possible/unverified 的变化。
3. 真实项目原始代码、显式标记的注入错误副本和修复副本。不得将注入问题冒充项目现有缺陷。
4. 报告溯源测试：证据每一步存在且指向正确源码；不能生成看似精确的虚构路径。
5. 智能体修复实验：统计正确修复、逃离分析、抑制规则、新增错误和失败，不只统计诊断是否减少。

首个实现切片至少覆盖项目内可解析同步调用、资源返回别名、关闭效果、正常／异常结果区分，以及未知导致未验证的传播。字段、递归或借用能力若尚未实现，必须保持明确的 unverified 边界，不能用本文设计替代实际验收证据。
