# 内置数据来源与日志效果模型（revision23）

前端区分精确内置字符串（Text）、递归内置 JSON 数据（JsonData）及未证明的值。事实来自语法构造和已建模调用，沿参数、返回值和控制流传播；普通 str/int/dict 注解本身不证明没有用户回调。

## 支持链

1. 非 bytes 字符串字面量得到 Text；数值、布尔、None 及递归只包含已知内置数据的字典/列表/元组得到 JsonData。
2. 默认 json.load / json.loads 的已建模精确输入得到 JsonData；自定义 decoder/hook 保持未知。
3. json.dumps 只在输入为 Text/JsonData 且使用默认编码器时建立无用户回调的效果模型；支持无选项或字面量 ensure_ascii。未知嵌套值、default/cls 等仍不通过。
4. Text 拼接，以及无额外格式选项、插值来源明确的 f-string，得到 Text。
5. 已知 Path 与 Text 拼接、Path 的构造/parent/mkdir、文件打开/写入/清理，接通日志写入链。

格式化、容器构造、解码/编码、目录创建等有失败边。结果只检查资源义务，不保证序列化成功、目录权限、内容或原子写入。未知赋值、外部调用、容器动态写入和模块替换仍产生 gap；不会把可变容器标为永久纯净。

## 输入和条件边界

函数入口参数不靠普通注解获得精确数据事实。可由已解析调用方的实际构造推断；显式 `--entry` 单独检查函数时，未提供契约的参数不会沿用被排除调用方的实参类型。显式入口契约仍按自己的准入和报告规则处理。

未知条件可能调用自定义 __bool__ / __len__，因此 if 的求真操作也会污染相关证明；while 已有对应检查。已有分支开发测试现在从明确的内置布尔调用方进入，不再暗中假设任意无注解参数没有副作用。

## 当前日志验收

`scripts/probe_log_data_scope.py` 保留三份冻结日志函数正文原字节，只在临时文件追加明确标注的开发调用方：Path 构造、日期字面量、递归内置记录。原始/注入错误/修复/未知分别为0/1/0/3，compare为resolved/became_unverified。

这不是 Museon 真实调用方验证，也不计入固定语料覆盖率。脚本另用 AST 读取真实 tick.py 的7个调用点并保存字段来源：时间戳均依赖 _now_iso(now_utc)，部分字段来自状态、阶段及计划值。datetime、状态加载及相应调用上下文尚未证明，不能仅凭现场字典语法断言值无回调。

默认固定语料仍5/11；hash在原manifest显式前提下仍3/3。没有编辑任何原始语料、预期或Museon代码。
