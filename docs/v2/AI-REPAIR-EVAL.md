# AI 修复效果实验 v1

状态：2026-09-13 已排入 P0；尚未运行 AI 对照实验，没有效果结论。

## 问题与预注册比较

检验：相同模型、任务、工具预算下，加入 llr 诊断能否增加正确修复，或减少达到正确修复所需的轮数/成本，同时不增加对正确代码的破坏。该实验不以 Rust 等价性为结论。

A 组：固定版本的 Ruff、Pyright，以及双方相同的任务说明、源码、业务约束与反馈流程。
B 组：A 组全部条件 + 固定语义版本 llr 的 JSON 诊断。不得给 B 组额外修复提示、答案或额外轮数。
首批固定每次最多 3 轮，每轮一次补丁及工具反馈；每次最多 10 分钟。运行前冻结精确模型 ID、推理配置、工具版本、token 上限和工具调用上限；两组完全一致。工具 token 也计入总预算。

后续若需解释收益来源，再增加“仅规则/位置、无证据链”的消融组；首批不扩大组合。

## 任务及样本隔离

1. 流程烟测：现有 read_file 的单函数错误、跨函数错误、正确原版，共 3 个任务，每组每任务 1 次，共 6 次尝试。用于检查发包、记录和评审，不用于声称产品有效。
2. 先导实验：新增 12 个独立来源任务，至少 8 个错误、4 个正确对照；覆盖别名、异常清理、跨函数、类方法和未知调用。按来源函数/调用链划分，不能把同一函数的重命名变体当独立样本。每组每任务 3 次独立尝试，共 72 次。开发使用过的任务不得进入这批；不足 12 个时如实报告，不拿开发语料凑数。
3. 后续外部有效性：待先导显示收益，再加入其他项目与规则类别。资源生命周期的结果不外推至完整所有权、借用或其他语言。

真实来源中的注入错误必须标为 synthetic_mutation，不能称为 Museon 既有缺陷。保留原始语料和哈希；仅在隔离副本上提交补丁，不修改 Museon。

修复参与者只收到单个匿名 task.py、业务约束和本组工具输出；不开放原始/修复配对、manifest、评审答案、仓库历史、其他组输出或当前对话。使用无历史的新上下文；全历史 fork 不合格。隔离不成立的尝试标 invalid，不计结果。不能根据 B 组能否分析来筛掉任务；分析覆盖率作为单独指标。

## 独立验收

llr 的退出码与 compare 只记录为辅助信号，不是正确性裁判。
评审只看匿名任务、业务要求与最终补丁，不看实验组别、诊断文本、轮数。先核对：保持接口、返回内容、错误处理和必须发生的读写；检查对象在所有相关路径的使用/关闭顺序。删除操作、吞掉异常、硬编码结果或禁用检查不能算修复。

保持当前“不执行或导入扫描目标 Python”约束。首批采用独立静态人工/智能体复核并记录逐条证据；证据不足标 inconclusive。不能声称运行时测试通过。评审分歧留存，由另一独立复核解决；无充分依据不强行二值化。
如将来加入动态 oracle，需单独设计可执行的隔离合成模型及安全边界，不直接运行 Museon 源码。

每次结果分别记录 semantic_verdict（correct/incorrect/inconclusive）、llr_verdict（verified/violation/unknown/tool_error）、coverage_change、functional_regression。unknown 不等于语义错误，也不能当作静态证明成功。人工确认的正确修复与 llr 能认证的修复分开统计。

## 指标与决策

主要指标：错误任务的独立确认修复率；按任务配对汇总，不把重复尝试当独立任务。inconclusive 单列，给出其全失败/全成功两种界限。正确对照统计被破坏比例及不必要修改比例。
次要指标：首次正确修复轮数、总 token、实际费用（无法读取时记 unavailable，不估造）、耗时、llr 未知率、分析逃逸、误报率、工具故障率。失败尝试也计入消耗；工具故障不冒充模型失败，主表保留并附排除故障的敏感性结果。

事先规定：烟测不作扩大投入的依据。先导若 B 没有修复率提升且没有成本/轮数改善，暂停扩展语法，审查误报、未知和诊断内容；若出现假修复被认证，优先修正确认逻辑。即使先导有收益，仍报告每任务结果和不确定性，扩大独立样本后才能声称稳定收益。不得看结果后换指标或排除难题。

## 独立候选抽样与运行限制

当前进程仅检查标准 OPENAI_API_KEY 是否存在，结果为 false；未读取或迁移任何其他凭据。此前 CLI 候选未满足准入，所以尚无可确认合格的模型 host。这是当前已检查接口的限制，不代表所有模型服务不可用，不需要用户提供秘密到聊天中。

`inventory_repair_candidates.py` 用 Python AST 读取源码（不导入/执行），从 apps 下带 with open(...) as name 的短函数生成候选；排除原开发语料文件、已用调用者文件、隐藏目录/内嵌 worktree、依赖及废弃目录。固定随机种子、每模块至多一个、不按 llr 结果筛选。首轮审计发现隐藏 worktree 重复，已拒绝该份清单并修正遍历；有效清单为 eval/repair/candidate-inventory.json：39 个候选函数中选 12 个不同模块候选，无解析失败。回归检查覆盖隐藏副本、开发文件排除、模块去重、哈希/重复结果及顶层不执行。

这不是已冻结的 12 道评测题：准入状态均 candidate_not_admitted。下一步独立审查函数/调用链重复、open 是否被重绑定、业务契约、错误构造及是否接触过开发；剔除有理由的条目必须保留原因并按固定次序补位。该抽样仅覆盖文件 with/open，不能代表类方法/所有权的广泛分布；为满足原计划覆盖还需补充其他机制分层，而非拿 12 个读取函数宣称全面验证。

## 用户要求立即推进后的烟测协议修正（结果产生前）

不能继续把模型自报可见工具当作实际隔离故障。先做一次只读取随机合成文件的实际工具探针，移除人为禁用 Code Mode host 所造成的启动错误。正式 12 题先导的强隔离要求仍保留。

为了验证流程，允许另行标注的 **exploratory trace-audited smoke**：使用 fresh ephemeral CLI、空 cwd、关闭开发文档/技能发现和用户配置，输入只含任务源码、共同业务要求和本组工具反馈；不传答案、来源身份或本对话。逐条审计 CLI JSONL，任何实际工具/命令/协作事件、非允许警告、超时或无效补丁使该次 invalid。没有工具事件只是观测到的无工具执行，不证明 host 强制隔离；这批不纳入确认性先导。

预设该次烟测模型 gpt-6-astra、medium、双方同配置，先执行每题每组一轮（6 次），单次 180 秒上限、输出响应限制 65536 字节、超过 60000 总 usage tokens 的尝试标 budget_exceeded（CLI 不支持本脚本的硬 token 上限，故不得宣称硬限额实验）。费用 unavailable，记录 usage 和 elapsed。随后在独立 fresh context 盲评每份补丁，不暴露分组及诊断；原版只作为业务背景，不能提供参考修复。该修改先于修复结果，不能事后按收益改回验收条件。
