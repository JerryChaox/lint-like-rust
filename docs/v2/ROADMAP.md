# 面向智能体的安全诊断重写

目标：把 AI 写代码、检查、修复、复查的反馈循环建立在明确的语义和证据之上。Python 是第一个语言前端，Rust 是实现语言。新实现与旧原型并存；旧 `llr check` 不等于新分析链。

## 本轮分工（首个里程碑已集成）

| 工作 | 所有者 | 交付与验收 |
|---|---|---|
| 语义规范 | semantics_v2 | 状态域、未知影响、调用、异常、借用和证明范围 |
| 类型前端复用验证 | frontend_research | 真实接口、依赖限制和可验证的技术选择 |
| 真实源码语料 | museon_corpus_v2 | 原文来源与哈希、错误变异、修复样例、能力要求 |
| 智能体诊断 | diagnostics_v2 | 带证据的义务协议；消失不等于修复的比较器 |
| CFG 与跨函数求解 | solver_v2 | 资源状态传播、别名、分支合并、未知影响和回归 |
| 项目级语义前端 | frontend_v2 | 模块/符号/调用目标解析和有限类型事实，输出 CFG |
| 集成与验收 | 主协调 | CLI、前后对照、真实源码验证、安装及状态记录 |

## 当前里程碑

第一条贯通链：已解析函数中创建资源，跨函数传递或返回，关闭后经别名读取，生成跨文件证据；修复后明确验证同一义务；未知调用导致未验证，不能获得虚假的“已修复”。

所有权、共享/独占借用从语义规范和 IR 开始设计。第一条集成链只验收资源生命周期，不借此宣称完成完整借用检查或一般 Python 类型分析。

## 后续验收顺序

1. 接入经验证的类型信息提供者，扩展调用目标解析；库模型补充外部效果。
2. 按规范实现权限转移、借用活跃区间与再借用，测量正常/异常分支。
3. 加入字段、容器位置与逃逸摘要，扩展循环、递归和跨模块规模。
4. 用真实语料的原始/变异/修复三组输入衡量检出和误报，而非只计测试数。
5. 智能体仅消费诊断尝试修复，记录正确修复率、轮数、新增错误与未验证退化。
6. 达到明确质量阈值后才默认替代旧命令、接入 Museon CI；随后验证第二语言前端。

设计文件不是已实现功能，最终实现范围见本目录 STATUS.md。
