# 面向智能体的诊断协议 v2

这是独立的已实现协议模块 `src/diagnostics_v2.rs`，不是旧 CLI 输出已经具备全部能力的承诺。前端和求解器需显式生成检查义务，并由适配层构建报告。

## 报告与证明范围

`Report` 包含协议版本、分析上下文、检查义务和分析缺口。`AnalysisContext` 记录语义版本、有效配置指纹、环境指纹。配置指纹必须涵盖规则选择、契约和求解预算；环境指纹必须涵盖语言版本、外部模型及前端版本。源代码版本不能放进可比性指纹，因为比较的目的正是检查代码修改。

每个 `Obligation` 是具体对象在具体操作处需要满足的条件，状态为：

- `verified`：在列出的假设和证明范围内，该条件成立。
- `violated`：报告违反条件的诊断；证据必须另外区分 definite 与 possible，不能将抽象路径误当成真实可达路径。
- `unverified`：信息或求解能力不足，无法得出结论。

检查义务清单不是全程序安全证明。零义务、零诊断都不等于安全。未解析的跨函数行为必须污染依赖它的调用者证明范围；不能只在被调用文件上记一个无关缺口。

`Gap.scope = None` 表示全项目不确定性，例如模块发现不完整。具名 scope 以工作区相对路径和限定符号名标识局部证明范围。

## 可解释证据

`Evidence` 包含规则性质（语言安全或额外安全策略）、确定性、对象身份、主位置、跨文件轨迹、被违反的约束和修复约束。`Obligation.assumptions` 单独列出成立前提，例如第三方契约。所有位置都带路径，避免调用者与被调用者行号混淆。

修复约束说明必须恢复的条件，而非保证可直接执行的补丁。例如“读取应发生在关闭之前”比“删除 close”更准确。消费方不得将建议自动视为保留原有语义的修复。

## 问题身份

`ObligationKey` 由路径、限定符号、规则、对象结构锚点、操作结构锚点组成。`issue_id()` 使用 UTF-8 字节长度前缀进行无损确定性编码，不依赖随机或平台相关哈希。

锚点由前端生成；不能使用当前行号作为主要身份。重复结构需要显式兄弟序号消歧。该协议只承诺位置变化时键可保持稳定，不承诺重命名、函数搬迁、插入相同兄弟操作后自动稳定。适配器若无法可靠匹配，应输出未验证，而不是猜测已修复。

## 两次检查比较

`compare_reports(before, after)` 输出 `resolved`、`still_present`、`new`、`became_unverified`。

只有同时满足以下条件，旧违规才成为 `resolved`：

1. 语义版本、配置、环境和协议版本可比。
2. 两边不存在重复义务键。
3. 修改后存在相同键、相同假设的显式 `verified` 义务。
4. 该义务的证明范围没有缺口，且没有全项目缺口。

旧诊断消失但义务也消失，必须为 `became_unverified`。这也意味着删除函数、删除操作和大幅重构目前不会自动被认证为修复；未来可加入经过验证的义务迁移或消除证明。配置变更不能“修复”旧问题。`new` 表示新报告出来，不等于新引入的缺陷。

这是保守的第一版局部证明比较。它没有实现完整程序等价证明，也不判断修复是否满足原业务需求。

## 验证

`tests/diagnostics_v2.rs` 验证消失进入未知、不带缺口的静默消失、局部与全局缺口、配置和假设变化、重复身份、真实验证、跨文件轨迹 JSON 往返及位置移动的身份稳定性。
