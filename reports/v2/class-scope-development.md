# 类调用范围开发验收

已安装 v2-resource-cfg-16。类方法解析从整个项目禁止 Unknown，缩小为调用连通分量内禁止 Unknown。

前端先建立限定调用目标的图，对 Call/Invoke 建立双向边，再从未知效果所在函数传播。双向传播用于覆盖未知调用者先替换方法、随后调用另一个函数创建实例和文件的情况。只做 callee → caller 传播会漏掉这个反例。

## CLI 验证

`llr analyze examples/v2/class-scope/before --entry case::run --format json`

| 输入 | analyze exit | 与 before 比较 |
|---|---:|---|
| Worker.finish 后经实例别名 read → self.contents | 1，LIFE001 | — |
| 调整为 read 后 finish | 0 | resolved，exit 0 |
| 文件打开前调用未知 external | 3 | became_unverified，exit 3 |

三个项目都包含未调用且带未知效果的独立 unrelated 函数。选定入口可忽略该独立函数；这不代表默认检查整个项目时可以忽略未知入口。示例、分析、求解与诊断保持零标注默认方式。

## 证明边界

资源诊断假定从已建模的模块定义状态进入指定入口，不包含此前未建模的任意入口调用历史；此假设已写进每个义务的 assumptions。模块初始化未知效果仍使选定入口不确定。未知调用者、未知被调用者以及共享方法连接的其他入口均保守传播不确定性。此方法尚非逐实例或时序敏感的效果摘要。

无状态普通类的继承、属性、字段和自定义构造器仍不支持；完整所有权、借用与外部类型服务未交付。不能将本例通过解释为 Python 获得 Rust 的全局安全保证。

284 项 Rust 测试、fmt、clippy、release 构建通过；安装 CLI 三态与比较实测通过。固定 Museon 语料仍为 5/11，3 个源片段及 11 个变体哈希验证通过，没有执行目标 Python。未重跑已曝光修复题来宣称 AI 收益。
